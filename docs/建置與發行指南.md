# 建置與發行指南

本文說明本機建置、測試、Pre-release APK 產出與 GitHub Release 流程。

## 1. 環境需求

| 工具 | 需求 |
| --- | --- |
| JDK | 17 以上 |
| Android SDK | Platform 36、Build Tools 35 以上 |
| Android Studio | 建議使用最新穩定版 |
| Gradle | 使用專案內 Gradle Wrapper 8.14.3 |
| Git | 用於版本控制與發行 |

確認 Android SDK 路徑：

```powershell
echo $env:ANDROID_HOME
```

若未設定，可在專案根目錄建立 `local.properties`：

```properties
sdk.dir=C\:\\Users\\你的帳號\\AppData\\Local\\Android\\Sdk
```

> `local.properties` 已列入 `.gitignore`，不應提交。

## 2. 取得原始碼

```powershell
git clone https://github.com/mark216tw/android-my-sites-01.git
cd android-my-sites-01
```

## 3. 常用建置指令

### 3.1 Debug APK

```powershell
.\gradlew.bat :app:assembleDebug
```

輸出：`app/build/outputs/apk/debug/app-debug.apk`

### 3.2 單元測試

```powershell
.\gradlew.bat :app:testDebugUnitTest
```

測試報告：`app/build/reports/tests/testDebugUnitTest/index.html`

目前包含 18 項測試：

- `UrlNormalizerTest`：9 項
- `SiteBackupCodecTest`：5 項
- `ThemeColorsTest`：4 項

### 3.3 Android Lint

```powershell
.\gradlew.bat :app:lintDebug
```

報告：`app/build/reports/lint-results-debug.html`

### 3.4 完整驗證

```powershell
.\gradlew.bat :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

## 4. Pre-release APK

### 4.1 建置

```powershell
.\gradlew.bat :app:assemblePrerelease
```

輸出：

```text
app/build/outputs/apk/prerelease/app-prerelease.apk
```

### 4.2 Build Type 設定

`app/build.gradle.kts`：

```kotlin
defaultConfig {
    applicationId = "com.example.mysites"
    minSdk = 26
    targetSdk = 36
    versionCode = 1
    versionName = "1.0.0"
}

buildTypes {
    release {
        isMinifyEnabled = false
        proguardFiles(
            getDefaultProguardFile("proguard-android-optimize.txt"),
            "proguard-rules.pro",
        )
    }

    create("prerelease") {
        initWith(getByName("release"))
        isMinifyEnabled = true
        isShrinkResources = true
        signingConfig = signingConfigs.getByName("debug")
        versionNameSuffix = "-prerelease"
        proguardFiles(
            getDefaultProguardFile("proguard-android-optimize.txt"),
            "proguard-rules.pro",
        )
    }
}
```

重點：

- **R8 壓縮**：`isMinifyEnabled = true`
- **資源縮減**：`isShrinkResources = true`
- **Debug 金鑰簽署**：`signingConfig = signingConfigs.getByName("debug")`
- **版本名稱**：`1.0.0` + `-prerelease` = `1.0.0-prerelease`
- **輸出檔名**：`app-prerelease.apk`

> `prerelease` 是測試發行版本，使用 Debug 金鑰簽署，**不可作為正式上線版本**。

### 4.3 驗證版本名稱

```powershell
& "$env:LOCALAPPDATA\Android\Sdk\build-tools\35.0.1\aapt2.exe" `
  dump badging "app\build\outputs\apk\prerelease\app-prerelease.apk" |
  Select-String "package:"
```

預期：

```text
package: name='com.example.mysites' versionCode='1' versionName='1.0.0-prerelease'
```

### 4.4 驗證簽署

```powershell
& "$env:LOCALAPPDATA\Android\Sdk\build-tools\35.0.1\apksigner.bat" `
  verify --print-certs "app\build\outputs\apk\prerelease\app-prerelease.apk"
```

預期簽署者：

```text
Signer #1 certificate DN: C=US, O=Android, CN=Android Debug
```

### 4.5 確認 R8 已執行

R8 mapping 檔應存在：

```text
app/build/outputs/mapping/prerelease/mapping.txt
```

也可由 APK 大小觀察；目前 `app-prerelease.apk` 約 1.42 MB（1,420,605 bytes）。

### 4.6 校驗碼

```powershell
(Get-FileHash "app\build\outputs\apk\prerelease\app-prerelease.apk" -Algorithm SHA256).Hash
```

`v1.0.0-prerelease` 的 SHA-256：

```text
18F17147501229E05C79D4311012DAE21A8C60CE0D07937E6F7EC0B69321B124
```

## 5. 建置版本比較

| 項目 | debug | release | prerelease |
| --- | --- | --- | --- |
| R8 壓縮 | 否 | 否 | 是 |
| 資源縮減 | 否 | 否 | 是 |
| 簽署 | Debug | 未設定 | Debug |
| 版本名稱 | `1.0.0` | `1.0.0` | `1.0.0-prerelease` |
| 用途 | 開發 | 預留正式發行 | 測試發行 |

正式上線前應：

1. 建立專用 release keystore。
2. 將金鑰與密碼放在安全位置，不提交到 Git。
3. 設定 `release` 的 signingConfig。
4. 啟用 R8 並完整測試。
5. 更新 `versionCode` / `versionName`。

## 6. GitHub Release 流程

本次使用 `gh` CLI 建立 Pre-release。

### 6.1 確認登入帳號

```powershell
gh auth status
```

本次使用帳號：`mark216tw`

### 6.2 建立 Release

```powershell
gh release create v1.0.0-prerelease `
  "app/build/outputs/apk/prerelease/app-prerelease.apk" `
  --prerelease `
  --title "我的站台 v1.0.0-prerelease" `
  --notes-file "docs/發行說明-v1.0.0-prerelease.md"
```

`--prerelease` 會將此版本標記為 **Pre-release**，不會被視為最新正式版本。

### 6.3 確認 Release

```powershell
gh release view v1.0.0-prerelease --json url,isPrerelease,assets
```

確認：

- `isPrerelease` 為 `true`
- assets 包含 `app-prerelease.apk`

## 7. 發行檢查清單

- [ ] 版本名稱正確（`1.0.0-prerelease`）
- [ ] `prerelease` 啟用 R8 與資源縮減
- [ ] 使用 Debug 金鑰簽署
- [ ] 單元測試通過
- [ ] Lint 通過
- [ ] APK 可安裝（建議在實機或模擬器確認）
- [ ] SHA-256 已記錄
- [ ] Release 標記為 Pre-release
- [ ] Release 說明包含「Pre-release 版本」警語
- [ ] README 與文件連結正確

## 8. 注意事項

- Debug 金鑰有效期與安全性不適合正式發行。
- R8 可能改變堆疊追蹤與類別名稱；除錯時請保留 `mapping.txt`。
- 目前尚未在實機或模擬器上完成 R8 版本的執行驗證。
- 每次重新建置 APK 後，SHA-256 可能不同，請重新計算。
